# odoo-typegen

Static type discovery and stub generation for Odoo addons.

The current CLI discovers Odoo addons from an addon directory, parses imported
Python model files, consolidates simple Odoo fields and methods, and emits
`.pyi` stubs.

## Usage

Install from PyPI:

```bash
pip install odoo-typegen
```

```bash
odoo-typegen ./addons ./typings
```

Equivalent explicit command:

```bash
odoo-typegen generate ./addons ./typings
```

When you have a local Odoo checkout, pass it to generate core overlays for
`Environment`, `BaseModel`, and `Model`:

```bash
odoo-typegen ./addons ./typings --odoo-path ./odoo
```

For an addon model like:

```python
from odoo import fields, models


class CrmLead(models.Model):
    _inherit = "crm.lead"

    x_base_code = fields.Char()
    x_is_priority = fields.Boolean()

    def action_mark_priority(self) -> None:
        pass
```

the generated stub currently looks like:

```python
# Generated by odoo-typegen.
from odoo.models import Model


class CrmLead(Model):
    x_base_code: str
    x_is_priority: bool
    def action_mark_priority(self) -> None: ...
```

The model name controls the addon output path:

```text
crm.lead -> ./typings/crm/lead.pyi
```

The CLI also emits Odoo overlay stubs:

```python
# ./typings/odoo/orm/environments.pyi
import typing
from crm.lead import CrmLead


class Environment:
    @typing.overload
    def __getitem__(self, model_name: typing.Literal["crm.lead"]) -> CrmLead: ...
    @typing.overload
    def __getitem__(self, model_name: str) -> typing.Any: ...
```

```python
# ./typings/odoo/orm/models.pyi
from odoo.orm.environments import Environment


class BaseModel:
    env: Environment

class Model(BaseModel):
    ...
```

## Using The Output

Point your type checker at the generated directory. For Pyright, add the output
directory to `stubPath`:

```json
{
  "stubPath": "./typings"
}
```

Then regenerate stubs when addon models change:

```bash
odoo-typegen ./addons ./typings
```

This makes Odoo lookups like `env["crm.lead"]` resolve to the generated
`CrmLead` stub in type checkers that use the output directory.

## Release

Build and validate the PyPI artifacts:

```bash
python -m build
python -m twine check dist/*
```

Upload with a PyPI API token:

```bash
python -m twine upload dist/*
```

## Nix

This flake exposes the CLI as the default package:

```bash
nix build
./result/bin/odoo-typegen --help
```

In another flake dev shell:

```nix
{
  inputs.odoo-typegen.url = "path:/home/jb/Projects/side-projects/odoo-typegen";

  outputs = { nixpkgs, odoo-typegen, ... }:
  let
    system = "x86_64-linux";
    pkgs = nixpkgs.legacyPackages.${system};
  in {
    devShells.${system}.default = pkgs.mkShell {
      packages = [
        odoo-typegen.packages.${system}.default
      ];
    };
  };
}
```
